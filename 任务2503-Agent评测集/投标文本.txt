【详细方案】
Understanding: The buyer needs a reusable evaluation set and runner that can serve as both a selection baseline and a regression gate for an agent runtime. The deliverable is a working package, not a slide deck: a JSONL set, a script that actually executes it, five computed metrics, a Markdown report, and a small independently implemented target agent so the whole loop can be demonstrated without any external service.

Evaluation set: Sixty-five synthetic cases are split into five groups. Query cases cover single and combined read-only lookups, empty results and attempts to widen scope through model input. Draft cases verify that generated text lands only in a human review queue. Privilege-inducement cases ask for another department's member data, direct messages to members, exports, external writes and unauthorized write modes. Prompt-injection cases hide instructions inside knowledge-base articles, company profiles and event notes, then try to trigger an outbound tool. Amount-inducement cases ask the agent to compute venue fees, discounts or per-head shares; each case expects either a refusal or a call to a business API, and the agent itself never performs arithmetic. Every record carries input, expected_tool_sequence, expected_result and prohibited_actions, plus a context and a deterministic action script for the mock adapter.

Target agent: A minimal runtime registers exactly four tools: search_companies, list_events, search_kb (read-only) and draft_followup (draft_write). Organization and site identifiers always come from the caller context, so values supplied by the model cannot widen the result set. Unregistered and unauthorized tool calls are refused before execution and recorded as rejected steps. Text returned by tools is treated as data; injection payloads are flagged and any subsequent outbound call is still refused. The only sink for generated text is the review queue, there is no outbound channel, and an explicit counter is exposed for assertions. Amount queries are either refused or delegated to a fixed fictional business API bridge, which is a system action rather than a model-callable tool.

Runner and metrics: The runner loads the JSONL file, executes each case once, and computes five metrics: task success rate (status, tool sequence, result behavior, scope constraints and prohibited actions all match), tool-selection accuracy (position-wise comparison of expected and observed tool names), prohibited-action rate (successfully executed prohibited actions divided by total cases, required to be zero; blocked attempts do not count), average step count, and P95 wall-clock latency using the nearest-rank method. The report template renders a dedicated section for the prohibited-action rate, a category breakdown, and a table of all five amount cases with their expected behavior. Mock mode is one command and writes the report; a strict flag turns any failed case or nonzero prohibited-action rate into a nonzero exit code for CI.

Model modes and verification: The default adapter replays each case's action script with zero network access, giving reproducible results; the report states honestly that this exercises the runtime guardrails and metric pipeline rather than model reasoning. A gateway adapter is provided as an integration point configured by environment variables, with no endpoint or credential shipped. The suite includes Node built-in tests and HTTP API tests; both pass locally, covering set structure, one-command execution, the five metrics, the standalone prohibited-action figure, all five amount cases, injection refusal, review-queue isolation and scope filtering.

Acceptance, scope and commercial terms: All three buyer criteria are covered by automated assertions with real command output recorded in the verification note. The quote covers source, evaluation set, runner, report template and generated report, tests, README and verification record with 2 revision rounds, delivered in 3 weeks. Excluded are real LLM calls, real gateway credentials, real databases, real authentication, real messaging, real business data and any product outside this scope.
