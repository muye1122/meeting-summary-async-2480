## 4. 五项验收的 API 实测证据

启动 `node mock-server/index.js` 后，用 Node `fetch` 顺序调用真实 API（节选关键输出）：

### ① 非当前步骤审批人被拒绝
```
提交 Q-1003（site_manager，当前步骤审批人 u-sup-01）
POST /sales/approvals/{id}/approve {"actor_id":"u-mgr-01"}
→ 403 NOT_CURRENT_APPROVER  expected=u-sup-01  actual=u-mgr-01
步骤日志仍为 2 条 pending，未被改写
```

### ② 提交后快照被篡改
```
提交 Q-1002 → 记录 snapshot_hash
POST /test/tamper-snapshot {"qid":"Q-1002"}
POST /sales/approvals/{id}/approve {"actor_id":"u-sup-01"}
→ 409 QUOTE_CHANGED_SINCE_SUBMIT  expected/actual 两个摘要不同
审批仍为 pending，步骤行数未增加
```

### ③ site_manager 依次审批（冻结时间）
```
POST /test/set-now {"now":"2026-11-24T00:00:00.000Z"}
提交 Q-1003
主管 u-sup-01 approve → approval=pending, current=u-mgr-01, quote=pending
经理 u-mgr-01 approve → approval=approved, quote=approved,
                        valid_until=2026-12-09T00:00:00.000Z（冻结时间 + 15 天）
GET /events → ["quote.approved"]
步骤日志（append-only）：1:pending → 2:pending → 1:approved → 2:approved
```

### ④ 驳回意见长度
```
POST /reject {"comment":"123456789"}  → 422 COMMENT_TOO_SHORT  actual_length=9
POST /reject {"comment":"1234567890"} → 200  approval=rejected  quote=rejected
```

### ⑤ 冻结时间下的 48 小时通知
```
冻结到 2026-11-24T00:00:00.000Z 后提交 Q-1003
25h 跑提醒 → approver_reminders=1, manager_reminders=0
49h 跑提醒 → approver_reminders=0, manager_reminders=1
通知日志：
  approver:u-sup-01:supervisor:25h | manager:u-mgr-01:site_manager:49h
再次跑提醒 → new notifications=0（同一审批+步骤+级别只提醒一次）
```

## 5. 契约与交付形态
- `/api/v1/meta`：tiers、层级权限上限、步骤序列、24h/48h 阈值、actor 注册表。
- `/api/v1/openapi.json`：OpenAPI `3.0.3`，覆盖提交、三种列表筛选、批准/驳回/撤回、提醒等路径。
- `/api/v1/contract/summary`：契约名、状态/动作、层级路由、15 天有效期与 stub 通知语义。
- 交付目录含要求的源码、配置、文档、迁移、测试文件；`npm install` / `npm run build` 自然生成的 `node_modules`、`package-lock.json` 与 `dist` 用于一键验收，非手写交付物。
- 未执行 `git init` / `git push`。所有人员、报价、金额均为虚构合成数据。
