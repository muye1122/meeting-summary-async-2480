## 二、三方案与九维度

- 方案 A：PostgreSQL 16 关系表（`nodes` / `edges`）+ 递归 CTE，复用现有技术栈。
- 方案 B：PostgreSQL + Apache AGE 扩展，openCypher 查询。
- 方案 C：独立图数据库（Neo4j Community 或 NebulaGraph）自托管。

九维度：私有部署与升级难度、与 pgvector 结合、两跳/三跳查询能力、事务与数据一致性、备份恢复、运维成本、许可条款、团队技能匹配、数据主权。

## 三、证据约定

对比表每个单元格含 `[R编号]` 引用，对应《参考链接清单.md》中的官方公开资料。本次为纯文档研究，**未安装新软件、未执行基准测试**：证据为官方文档事实，"能力有无"引用官方功能描述，"优劣判断"为基于事实的工程推断。所有示例表结构、字段与数值均为虚构占位，无任何客户信息。

## 四、核心结论

推荐**方案 A** 作为一期方案；方案 B 作为同一数据库实例上的二期演进选项；方案 C 因双系统一致性、运维、许可与技能成本在一期排除。迁移草案共 7 步。
