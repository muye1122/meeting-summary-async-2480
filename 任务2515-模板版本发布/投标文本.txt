【详细方案】
Understanding: The buyer needs controlled release of SOP templates. POST publish with release_notes must validate that the draft has at least one step, that all mandatory step fields are filled and that release_notes is non-empty; on success it freezes the draft as a new version (version_no+1) with a snapshot, and newly triggered instances must always use the latest published version. POST disable must stop new instance generation without interrupting instances already running. Version isolation means the template snapshot is copied into an instance at creation time, so subsequent publish, disable or draft edits never affect that instance. Migrating a running instance to a new version is explicitly out of scope. Both publish and disable write audit records carrying a diff summary against the previous version (added, deleted and modified steps).

Plan:
1. Implement the pure diff module (step matching by id, field-level before/after changes, structured and one-line diff summaries).
2. Implement publish with 422 validation, version_no bump, deep-copy snapshot freeze and audit write.
3. Implement disable with 409 rejection of new triggers, uninterrupted execution of running instances and audit write.
4. Implement instance trigger from the latest published version, snapshot isolation and instance completion endpoints.
5. Build the React 18 + Vite 6 demo showing draft editing, versions, instance snapshots and audit diff summaries.
6. Ship Dockerfile, docker-compose.yml, README with honest limits, a verification record, Node unit tests and Playwright integration tests for all four acceptance criteria.

Acceptance criteria - every customer criterion addressed explicitly:
- Criterion 1 (v1 instance keeps the old step-3 time limit after v2 changes it; new instance uses v2): the integration test publishes v1, triggers an instance, edits the draft, publishes v2 with a 48-to-24 hour change, then asserts the old instance snapshot and digest are unchanged while a new instance reports version 2 and 24 hours. A draft-only edit is also proven not to leak into a new instance.
- Criterion 2 (disable rejects new triggers, existing instances complete): the integration test disables the template, asserts 409 TEMPLATE_DISABLED on trigger, then completes every step of the already running instance and verifies status completed with its original snapshot intact.
- Criterion 3 (empty release_notes returns 422): missing, empty and whitespace-only notes all return 422 RELEASE_NOTES_REQUIRED and write no audit record, while a valid note publishes successfully.
- Criterion 4 (audit contains added/deleted/modified diff summary, stub assertion): after deleting one step, adding one step and changing a step's time limit, the publish audit record's diff_summary contains added step-5, removed step-4 and modified step-3 with the before/after value, and its text names all three categories; the disable audit record carries the same three lists with zero counts.
